# Product, UX and security decisions

This is the decision record for the R19 and R19.1 implementation shipped in this kit. Each entry states **Decision — why — where in code**. Historical findings remain visible with their final disposition so an installer does not accidentally restore a superseded behavior. Adapting an integration seam must preserve these invariants.

The plans and review records were read from the source application's private working tree. They are summarized here; the private plans, execution logs, names, addresses and deployment details are not distributed. This document records design and source-review history, not a claim that this portable kit has run as a standalone app or been deployed.

## R19 binding calls C1–C12

| ID | Decision | Why | Where in code |
|---|---|---|---|
| R19-C1 | Store raster bytes in a separate Postgres `bytea` table; browser output is at most 1920 pixels per edge and 2 MiB, WebP with PNG fallback. Do not install object storage, signed uploads or a new storage secret. | Lists must not load binary content; bounded uploads fit action requests and reduce database growth. Browser MIME and metadata are untrusted. | `DB` migration 0001; `L/prepare-image.ts`, `L/image-metadata.ts`; `S/images.ts`; `A`. |
| R19-C2 | Authenticate and authorize the image's parent before selecting bytes. Serve sniffed raster MIME with `private, no-store`, `nosniff`, and inline display disposition. | A guessed attachment ID, removed file or shared cache must not disclose private screenshots. No bytes/data URLs go into RSC/action/list DTOs. | `API/images/[id]/route.ts`, `S/images.ts`, `S/queries.ts`, `L/types.ts`. |
| R19-C3 | Use effective `bugs.report` and `bugs.triage`, rather than an ADMIN shortcut. Report is granted to every default role; triage defaults to the two administrative source roles. Preserve explicit saved true/false grants. | Existing hosts may delegate or revoke capabilities independently of role names. Mine is always owner-scoped, even for a triager. | `S/access.ts`, `S/queries.ts`; auth/permissions adapters in `REF`; `P/` guarded pages. |
| R19-C4 | All creates, comments, workflow edits, read markers and removals use named `withAction` boundaries with service-level checks. | UI hiding or a top-level page guard does not authorize a mutation; avoid a parallel REST write implementation. | `A`; `S/commands.ts`, `S/files.ts`; action guard in `REF`. |
| R19-C5 | Preserve reports, comments, history and attachment evidence; no hard delete. A triager removes bytes once by setting content NULL with actor/time/reason. Cancellation requires a reason. Enable RLS with zero policies plus DELETE/TRUNCATE guards. | Keep audit evidence and support explicit privacy removal without opening public SQL access or silently erasing history. Privacy text redaction must remain possible. | `DB` migrations 0001/0003; `S/commands.ts`, `S/files.ts`; privacy adapter in `REF`. |
| R19-C6 | Enforce the explicit transition graph, nullable priority, and an active effective-triager assignee. | Prevent arbitrary status jumps, unauthorized reassignment and stale concurrent writes. | `D`, `S/commands.ts`, `S/access.ts`, `U/bug-detail.tsx`. |
| R19-C7 | Capture bounded path/allowlisted filters, viewport and UA diagnostics; derive actor and build SHA on the server. No cookies, storage dumps, arbitrary URL or client-forged identity. | Diagnostic context can otherwise leak search/customer data or become a forged external link. | `L/context.ts`, `L/user-agent.ts`, `S/context.ts`; widget context capture. |
| R19-C8 | Enforce rolling limits of 5 reports and 30 comments per actor per 10 minutes in the DB, under advisory transaction locks. | An in-memory limiter is bypassed by multiple instances/tabs and cannot serialize count-and-insert. | `D`; `S/rate-limit.ts`, `S/commands.ts`, rate-limit DB tests. |
| R19-C9 | Mount one permission-gated shell FAB; preserve accessible dialog/draft/focus behavior and collision avoidance. English controls/headings, Thai help; token styling and text at least 12px. | The feature must work across authenticated pages and phones without covering existing controls. R19.1 replaces the original editor presentation, not these shell/accessibility constraints. | `U/bug-report-widget.tsx`, `U/bug-report-form.tsx`; floating-action/UI adapters in `REF`, `examples/`. |
| R19-C10 | One existing nav-count provider/poller supplies NEW and unread-report badges, including More on phones. A displayed own detail acknowledges only its snapshot watermark. | Avoid duplicate polling, invisible mobile activity, and racing replies being cleared unseen. | `S/nav-counts.ts`, `U/reporter-read-effect.tsx`; nav adapter in `REF`, `examples/`. |
| R19-C11 | Reuse personal-webhook/outbox delivery with current eligibility and a pause switch. Send only opaque safe summary, status and a trusted internal link; never free text or bytes. Delivery cannot fail an already committed action. | Customer names cannot be reliably removed from arbitrary summaries. Missing/broken webhooks must not cause public-channel or API fallback. | `S/notifications.ts`, `L/chat-notice.ts`; Google Chat/jobs adapters in `REF`; `A`. |
| R19-C12 | Retain all eight original test intentions and add permissions, binary validation, privacy, query stripping, quotas, preservation and reporter→triager→unread→read proof. | Porting persistence/auth must not weaken accepted behavior or security. | Adjacent unit/DB/action/route tests, `E2E`; host verification instructions in `README.md`. |

## R19 detailed decisions D1–D5 and shared contracts

| ID | Decision | Why | Where in code |
|---|---|---|---|
| R19-D1.1 | Trim summary (1–200), optional description (≤4,000), comment body (≤4,000) and nonempty cancellation/removal reason (1–500). | Bound storage/action payloads and avoid meaningless or whitespace-only records. | `D`, `L/input.ts`, `A`, `S/commands.ts`. |
| R19-D1.2 | A comment requires text or one image; R19.1 additionally supports explicit pending PDF intent. Store absent body as NULL; no localized image sentinel in the database. | Attachment-only messages are valid without pretending placeholder copy is user text. Empty ordinary comments remain invalid. | `L/input.ts`, `S/commands.ts`, `U/bug-comment-thread.tsx`, migration 0003. |
| R19-D1.3 | Commit report/comment, image, history, audit and applicable outbox work atomically. A later PDF request is intentionally separate. | A rejected raster/action must not leave an orphan or half-created comment. PDF retry must not duplicate a saved report/comment. | `A`, `S/commands.ts`, `S/files.ts`, `DB`. |
| R19-D1.4 | Generate business IDs on the server. Bind the client UUID request key to actor and original parent, look up a successful replay before consuming quota, and retain the exact uncertain payload/key. | Network loss can follow commit; retries must not duplicate rows, history, bytes, unread increments or cards. Reusing a comment/PDF key for another report is refused. | `S/commands.ts`, `S/files.ts`, `DB` unique constraints; widget/thread/PDF retry state. |
| R19-D1.5 | Provide no summary/comment edit, comment delete, image replacement or restore action. | Preserve source scope and historical evidence; privacy repair is a separate controlled adapter concern. | Exports of `A`; `S/commands.ts`, `S/files.ts`; immutable attachment triggers in `DB`. |
| R19-D2.1 | Allow new→in_progress/cancelled; in_progress→done/cancelled; done/cancelled→in_progress. Refuse new→done. | Duplicates may be cancelled immediately, while completion requires actual triage and reopening remains explicit. | `D::canTransitionBugStatus`, `S/commands.ts`. |
| R19-D2.2 | Lock/reload the report and compare its version before edits; safe stale-state refusal preserves the user's draft. Same-status saves are no-ops. Priority/assignee-only changes increment version without status history or unread activity. | Prevent silent overwrite, invented history and misleading reply badges. | `S/commands.ts`, `U/bug-detail.tsx`. |
| R19-D2.3 | Recheck active/current effective triage for assignees; retain an old unavailable assignee as history and allow reassignment. | A historical staff ID neither grants access nor justifies a new assignment. | `S/access.ts`, `S/commands.ts`, `S/queries.ts`, detail controls. |
| R19-D2.4 | Use namespaced per-actor advisory transaction locks, DB clock after lock acquisition, and successful inserts in `(now − window, now]`. Acquire quota lock before report lock. | Concurrent workers must observe one quota state and one lock order. Cancel/removal does not recover rate or uploaded-byte capacity. | `S/rate-limit.ts`, `S/commands.ts`, `S/files.ts`. |
| R19-D3.1 | Keep monotonic activity/read counters with `0 ≤ read ≤ activity`; count reports, including terminal reports, with unseen other-triager activity. | A timestamp alone cannot safely acknowledge racing replies. One report with several replies still counts once. | `DB`, `S/commands.ts`, `S/nav-counts.ts`, `S/queries.ts`. |
| R19-D3.2 | Increment activity for another triager's comment or real status change, excluding self activity and priority/assignee-only edits. First late triager PDF arrival increments once too. | Notify the reporter about meaningful unseen content while avoiding self-notifications and replay noise. | `S/commands.ts`, `S/files.ts`, `S/notifications.ts`. |
| R19-D3.3 | Read detail/report counter/latest 50 comments/latest 50 status changes in a read-only repeatable-read snapshot. Older-page results have no new watermark. | The acknowledged sequence must describe content actually available in that detail snapshot. Latest activity must not be hidden behind an oldest-first page. | `S/queries.ts::getBugDetail`, `loadBugThread`. |
| R19-D3.4 | Owner-only mark-read advances to `max(previous, min(seen,current))` after display; it does not touch triage version/business update time. Prefetch/list rendering never marks read. | A delayed mark-read cannot erase a later reply; reading is not a business edit. | `S/commands.ts::markBugRead`, `U/reporter-read-effect.tsx`. |
| R19-D4.1 | Guard local inputs at 15 MiB before decode; downscale before annotation, flatten on Send, verify encoded Blob type/size, and retry bounded quality/resizes to meet 2 MiB. | Native-resolution input and PNG fallback can otherwise exceed action/database bounds. Failure must preserve the draft. | `L/prepare-image.ts`, `U/bug-report-form.tsx`, widget export; `U/image-input.tsx`. |
| R19-D4.2 | Parse bounded PNG/JPEG/WebP headers/containers on the server. Require nonzero ≤1920 dimensions, ≤3,686,400 pixels and ≤2,097,152 bytes; reject malformed/truncated raster and animation. | Extensions, browser MIME and client dimensions are not a security boundary. No undeclared transitive decoder is required. | `L/image-metadata.ts`, `S/images.ts`, validation tests. |
| R19-D4.3 | Report-dialog GIF input is converted to its first still frame in R19.1; server-stored formats remain PNG/JPEG/WebP. The comment picker accepts PNG/JPEG/WebP and PDF. Never accept SVG as image content. | Preserve the newer UX while keeping the original persisted-raster boundary. | `L/report-dialog.ts`, `L/prepare-image.ts`, `L/image-metadata.ts`. |
| R19-D4.4 | Revoke object URLs on replacement/close/unmount. Never persist image or text drafts in local/session storage or IndexedDB. | Avoid leaked local resources and durable copies of potentially sensitive screenshots. | `U/bug-report-form.tsx`, `U/image-input.tsx`, `L/prepare-image.ts`. |
| R19-D4.5 | Preserve image associations, MIME, dimensions and original byte count after one-way removal; do not overwrite the first removal evidence on repeat. Allow controlled metadata privacy repair. | Removal must be irreversible in the live row and auditable without blocking later text redaction. | `DB` image/file mutation guards; `S/commands.ts`, `S/files.ts`, removal UI. |
| R19-D4.6 | Load private same-origin images directly, bypassing a public/shared optimizer. Return uniform 404 for absent, unauthorized or removed attachments and 401 for unauthenticated binary requests. | Cache layers and existence distinctions can disclose private files. No signed/public URL, ETag/304 cache path or base64 DTO is needed. | `API/images/[id]/route.ts`, `API/files/[id]/route.ts`, `S/images.ts`, `S/files.ts`, `U/bug-image-viewer.tsx`. |
| R19-D5.1 | Validate a known same-app route and separate query; reject unsafe/external/API/token locations and fall back safely. Keep only validated single status/priority values on Bugs and status on Mine; strip q, duplicates, unknown keys and fragments. Cap canonical location at 2,048 characters. | A report must not export search terms, credentials or arbitrary browser state. The route list is a documented host seam. | `L/context.ts` and tests; widget context capture. |
| R19-D5.2 | Bound viewport to positive integers ≤16,384; server UA to 2,048; finite parsed OS/browser/device labels and dotted numeric versions ≤32. Invalid SHA becomes NULL. | Diagnostics are best effort and cannot be trusted for auth or retained as unbounded free-text parsed fields. | `D`, `L/input.ts`, `L/user-agent.ts`, `S/context.ts`. |
| R19-D5.3 | Use only a generic `Bug report <short id>` summary in cards, plus status and a trusted app link. No names, author/customer labels, submitted summary/body, image/PDF, raw context, dynamic external link or action token. | Phone/email masking cannot establish that a title contains no customer name. Full content stays behind app authentication. | `L/chat-notice.ts`, `S/notifications.ts`, Google Chat adapters in `REF`. |
| R19-DATA-1 | Keep reports, comments, status history and raster bytes separate; add a sibling PDF table in R19.1. Restrictive FKs, partial one-slot indexes and composite comment/report FKs enforce identity. | Lists remain narrow, cross-report attachments are impossible, and raster constraints need not be weakened for PDF. | `DB` schema and migrations 0001/0003. |
| R19-DATA-2 | Use UTC timestamptz and stable created-time/UUID keyset pagination (default 50, maximum 100), opaque bounded validated cursors, and ISO date DTOs. | Stable pagination must survive equal timestamps without loading whole threads or serializing server objects. | `DB`, `S/queries.ts`; time adapter in `REF`. |
| R19-DATA-3 | Project explicit scalars/metadata only; no row spreads, binary buffers, credentials, storage paths, Files or data URLs in client props/results. Mine omits other staff IDs and raw UA. | A server component boundary is not permission to disclose the underlying row. | `S/queries.ts`, `S/files.ts::bugPdfFields`, `L/types.ts`, privacy projection tests. |
| R19-PRIV-1 | Classify report context/summary/description, comment body and status reasons as scrubbed text; classify attachments/manual metadata for explicit review. Keep structured identity/status evidence. | Existing strong-identifier cleanup can redact text but cannot OCR screenshot/PDF content or reliably infer name-only personal data. | Privacy adapter in `REF`, `INTEGRATION.md`; `S/commands.ts` removal flow. |
| R19-PRIV-2 | Manual image/PDF/name review is required; zero inventory counters do not prove pixel/name erasure. NULL-ing live bytes does not erase backups. No new destructive retention job or external-deletion guarantee. | The privacy system's limits must be explicit, not hidden behind a table inventory exemption. | `INTEGRATION.md`; image/PDF removal UI and preservation SQL. |
| R19-AUDIT-1 | Audit bug reported/commented/status/priority/assignee/image/PDF mutations with IDs/enums/outcomes only. Keep reasons in protected owning rows; no noisy per-read audit event. | Logging FormData, free text or bytes would create an uncontrolled second copy of private content. | `A`, `S/commands.ts`, `S/files.ts`; event/logging adapters in `REF`. |
| R19-AUTH-1 | Guard pages before reads, but independently refresh actor/grants in services and recheck after waits/locks. Missing and forbidden reports look the same to reporters. | Permissions can change while a request waits, and direct service/API access must not bypass the UI. | `P/` pages, `S/access.ts`, `S/queries.ts`, `S/files.ts`. |
